# Incident record — 2026-10-23 — Railway account/project compromise

**Status:** open, investigating
**Severity:** suspected critical (platform-level access to app secrets and data)
**Incident lead:** TBD
**Runbook used:** `docs/incident-response.md`
**Last updated:** 2026-10-23

## Summary

On 2026-10-23 it was reported that the Railway account/project hosting Study
Buddy was compromised. The nature of the access (account login, stolen token,
rogue deployment, or leaked secret) and whether production data was read are
**not yet confirmed**. This record is precautionary until the evidence says
otherwise.

## What is confirmed

Local repository inspection on 2026-10-23 (read-only):

- `origin` is `github.com:keanehatescoding/strathmore-study-buddy`, branch
  `master`.
- `HEAD` is `1b07535` ("fix(moodle): don't treat HTML files as a login page"),
  committed 2026-10-17 11:55 +0300.
- No commits on any ref since 2026-10-17; no unexpected authors; no reflog
  entries suggesting a force-push.
- `.env` has never been committed; no local git hooks were added.
- Working tree at the time of inspection was clean.

This rules out a poisoned local clone or a pushed commit as the *known*
vector. It does **not** rule out a deployment made with `railway up` (which
bypasses GitHub), a stolen Railway token, or account takeover.

## Blast radius (assume all of it until ruled out)

| Data/asset | Present in this app |
|---|---|
| User emails + sign-in records | `users` |
| Course material, resources, extracted text | `courses`, `topics`, `resources` |
| Assignments and due dates | `assignments` |
| Quiz/review history, flags, notes | `quiz_*`, `review_*`, `item_flags` |
| Encrypted Moodle tokens | `users.moodle_token` |
| Encrypted Google refresh tokens (Classroom + Drive read) | `users.google_refresh_token` |
| Session signing / token encryption key | `SECRET_KEY` env |
| Outbound mail capability | `RESEND_API_KEY` |
| LLM spend | `LLM_API_KEY` |
| Deploy/execute capability | Railway services |

Passwords are not stored: Moodle passwords are held only in memory for the
`login/token.php` exchange. There is no payment data.
